# Two-way modal contact — contact forces in a cube stack

Backing note for the write-up to Sheldon. Everything here is generated by
`benchmarks/network/report_sheldon_contact_forces.py` (analysis only — no solver
code was changed). Figures: `contact_forces.png`, `abd_comparison.png`. Numbers:
`contact_forces.json`.

**Scene** (`scenes/reduced_cargo_network.py`): a reduced-modal slab carries three
0.6 kg cubes — a plain `resting` control cube, an `impactor` dropped from 0.22 m,
and a 3-high zig-zag stack `base → mid → upper`. `base` rests on the slab; `mid`
and `upper` touch **only the cube beneath them** (box-box contact, no support).
Each cube carries its own reduced elastic modes. `h = 1/120`, 12 iters × 4
substeps, AVBD, CPU. m·g = 5.886 N.

---

## 1. What the generalization is

DCR's modal response is now a **native constraint** shared between bodies. One
unilateral contact row is written on the *deformed* contact point of **both**
participants:

```
C = C_rigid + (Ĝ_A · a_A − Ĝ_B · a_B),     Ĝ_X = n̂ᵀ R_X Φ_X
```

The **same** contact multiplier `f` both (i) pushes the rigid bodies apart and
(ii) drives each participant's modes (`+Ĝ_A f` on A, `−Ĝ_B f` on B). Newton's
third law is built in, so the coupling is two-way and momentum-consistent by
construction — not a post-solve kick. The support contact (cube ↔ slab) and the
box-box contact (cube ↔ cube) are the **same row type**; that is the whole
generalization — *every* body with modes participates, including stacked cubes
that only ever touch another cube.

---

## 2. Contact forces at the corners  (figure `contact_forces.png`)

The per-corner / per-joint normal forces are read straight off the solver's
contact multipliers (`λ`, in N; Σ over a body's corners = the weight it carries).

**(a) The ledger is statically exact — each joint carries the weight above it:**

| joint | measured (settled) | expected | error |
|---|---|---|---|
| resting cube → slab | 5.889 N | m·g = 5.886 | 0.06 % |
| base cube → slab | 17.99 N | 3 m·g = 17.66 | 1.9 % |
| base ↔ mid (box-box) | 11.93 N | 2 m·g = 11.77 | 1.4 % |
| mid ↔ upper (box-box) | 5.82 N | m·g = 5.886 | 1.1 % |

No per-joint tuning — the shared-multiplier contact balances the tower on its own.

**(b) The plain resting cube** shares its weight ~evenly across 4 corners
(m·g/4 = 1.47 N each; a small diagonal split 1.39 / 1.56 N from the slab's mode
shape under it). This is the pre-existing one-way behaviour — the control.

**(c) The base cube (stack foot)** carries 3 m·g, split **unevenly** across its
corners (2.7 → 4.1 → 4.8 → 6.3 N) because the zig-zag stack's COM leans toward the
`+x −z` corner. Physically correct load transfer, and each corner carries a
visible ring modulation on top.

**(d) It is genuinely two-way.** The `upper` cube touches only `mid`, which touches
only `base` — it is two box-box hops from the slab. With the network ON it rings
(`|a|` peak ≈ 1.1×10⁻⁵); with the network OFF it is `|a| ≡ 0`, structurally dead.
So the vibration reaching the top cube arrives *only* through the shared contact
constraints. Bonus: the modal compliance also **smooths the contact force** — the
mid↔upper joint-force ripple drops from ±2.72 N (OFF, rigid-on-rigid chatter) to
±1.48 N (ON) while the mean stays at m·g.

## 3. Would ABD help?  (figure `abd_comparison.png`)

Short answer: **ABD is already wired in and interchangeable, but it does not change
the coupling — it is a different reduced basis for the cargo's own deformation.**

- ABD (`kind="abd"`) is a co-rotated affine body: a 9-DOF `F = vec(F−I)` on top of
  the rigid frame, its corner Jacobian `B_c` playing exactly the role of the modal
  `Φ_c`. It drops into the **same** box-box network with no special-casing.
- **The static contact ledger is basis-independent** (fig b): rigid, modal, and
  affine cubes all settle to the same m·g multiples at every joint. Force balance
  doesn't care which basis the cube flexes in.
- **Only bodies with a basis ring** (fig a): the modal cube and the affine cube
  both transmit a ring to the top of the stack; the pure-rigid cube (0 modes)
  cannot ring at all (`|a| ≡ 0`).
- **The physics they capture differs.** The affine subspace represents uniform
  stretch/shear/rotation; it **cannot** represent the bending/plate ring modes that
  are the whole point of DCR. So ABD is attractive for cheap, robust
  (IPC-style) contact and gross deformation, but the modal `Φ` basis is what
  carries the distant-collision *ring*.
- **Caveat (honest):** in this stack the affine flex showed a slow secular buildup
  over 3 s rather than a clean bounded ring — it would need the same energy
  (passivity) governor the modal path has before I'd claim anything about its
  stability.

**Recommendation:** keep modal `Φ` as the headline basis (it is the DCR object and
the one with the energy bound); treat ABD as a supported, swappable cargo basis and
a future-work direction, not a replacement.
