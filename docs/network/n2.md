## What this generalizes

Before N2, only SUPPORT_CONTACT rows carried modal columns: a cargo cube rings
the slab, and the slab rings the cube (one shared multiplier, ∂C/∂q = −U_y,
∂C/∂a = +G_a). A cube stacked on ANOTHER cube felt only its rigid pose — the
lower cube's *flex ring* never reached it, because BOX_BOX rows carried no modal
columns.

N2 adds modal columns to BOX_BOX rows between cargo bodies. The gap is read
against BOTH participants' deformed contact points:

```
C(z, Q) = n̂ · [ (x_A + R_A(r̄_A + Φ_A a_A)) − (x_B + R_B(r̄_B + Φ_B b_B)) ]
∂C/∂a_A = +n̂ᵀ R_A Φ_A        ∂C/∂b_B = −n̂ᵀ R_B Φ_B
```

so the ONE shared box-box multiplier loads both cubes' a-blocks with opposite
signs (Newton's third law on Q). The slab support is the degenerate participant
of this same gap — zero rigid DOFs, world-fixed field U_y — i.e. the pre-N2
support row is the special case.

## Implementation (host-only, no kernel change)

The augmented q-block already solves over `Q = [q_support; a_b0; a_b1; …]`. N2 is
a host-only addition to that block:

1. `_build_net_rows` (substep begin, after the box-box emit; staggered like
   `_cargo_freeze_and_W`): scan the emitted BOX_BOX rows (read from the `c_*`
   device arrays via `.numpy()` — normal in `c_world_anchor`, bodies in
   `c_body_a/b`, contact points in `c_off_a/b`), keep those with ≥1 cargo
   participant, and freeze each participant's modal gradient `G = n̂ᵀ R Φ_c`. Φ_c
   is the nearest cube corner's block (`_corner_snap_pid` — box-box contacts land
   on corners/edges, the modal field is smooth; `# DEVIATION §N2 sampling`).
2. `_solve_q_block_cargo`: gather each frozen net row into the block with
   `Ws = [−G_A in A's a-cols | +G_B in B's a-cols]`, `C = C_geom − Ws·Q` (rigid
   gap read LIVE, modal columns frozen — the same staggering the support loop
   uses). One multiplier `f = min(ρC + λ, 0)`, `g -= Ws·f`, `H += ρ Ws Wsᵀ`.

Feasibility was mapped first: BOX_BOX rows live only in the `c_*` dynamic region
and are `.numpy()`-readable after emit, and the q-block runs after emit — so the
modal coupling needs no warp-kernel change. OFF (or no cargo box-box pair)
`_net_rows` is empty ⇒ bit-identical.

## Results (`tests/…/test_modal_contact_network.py`, all green)

Setup: lower cube L on a modal slab (support cargo); upper cube U stacked on L
(box-box only, NO support rows — so U's modes are reachable ONLY through the
network). Also the full 4-cube scene (`scenes/reduced_cargo_network.py`).

- **The core discriminator.** U's modal amplitude is **exactly 0** with the
  network OFF (structurally uncoupled) and **rings** with it ON. In the 4-cube
  scene the stacked cube's peak `‖a‖` goes `0.000e+00 → 2.5e-5`, comparable to
  the base cube (3.4e-5) it rests on — while the left resting-cube control is
  unchanged (3.07e-5 → 3.10e-5).
- **Two-way / counterfactual.** Freezing the lower cube's ring (`_freeze_adot`,
  ȧ_L ≡ 0) reduces the upper cube's response — part of U's ring is genuinely fed
  by L's ring (the rest is the direct box-box contact impulse exciting U's own
  modes). Honest: it is *not* pure ring-transfer.
- **Stability.** The modal coupling is bounded over 600 steps (‖a‖ < 1, no NaN,
  no tunnelling) including an offset (non-corner-aligned) stack.
- **OFF-parity.** Flag OFF reproduces the baseline box-box trajectory
  bit-identically; the full `tests/avbd_native/` suite is 0 new failures.

## The rigid-ride half — now implemented, stable with friction (N3 partial)

The N2 result above is **modal↔modal**: both cubes' *modes* ring through the
shared contact. The complementary **rigid-ride** effect — the lower cube's flex
also pushing the upper cube's *rigid body* — needs the box-box PRIMAL/DUAL gap to
see the flex. It is now wired: `_bake_ride_crest` writes
`c_rest[cidx] = −(Ĝ_A·a_A − Ĝ_B·a_B)` for each box-box net row (host-side, from
the **live** a each q-block sweep), and the box-box branches of
`primal_update_6dof` / `dual_update_6dof` read `C -= c_rest`. So the gap is the
fully-symmetric unified `C = C_rigid + (Ĝ_A·a_A − Ĝ_B·a_B)` — the same flex now
drives `z` as well as `a`. Behind `_modal_contact_ride` (default OFF, requires the
network on); OFF, box-box `c_rest ≡ 0` ⇒ **bit-identical** (the full box-box /
cargo / stacks suite is green).

**The first cut** (frozen-per-substep flex, no gate) tunnelled an offset
frictionless stack (`y → −7.9 m`). **This version** tames the pre-registered N3
pump — two resonators through an on/off unilateral contact — with three
ingredients: (a) a **per-joint compressive-engagement gate with hysteresis**
(`_ride_gate`; a grazing/lifting contact never rides), (b) an **under-relax**
(`_ride_relax = 0.35`), and (c) a **capped flex** refreshed from the live a each
sweep (not stale). Result:

- **Stable with friction** — the demo 3-high offset stack (μ=0.4) holds
  base/mid/upper at 0.05 / 0.15 / 0.25 for the full run, finite; 2-cube stacks
  (aligned and offset, μ=0.4) stay up over 500 steps; settled frictionless stacks
  are stable too.
- **The rigid body responds to the flex.** `δy = y_upper(ride ON) − (ride OFF)`
  isolates the ride: a **bounded, flex-scale** rigid response (~15 µm rms in the
  ring band, ≤ 0.2 mm total over 4 s) that is **exactly zero with the ride off**.
  The stacked body genuinely moves with the surface beneath it, at the flex scale.

**Honest limits (both pre-registered as the N3 gate).** (i) A **frictionless
offset stack under a hard drop transient still tunnels** — the ride tips the
metastable frictionless tower and no gate/relax/cap value fixed it (tried
instant-gate-down, tight, very-tight — the last made it *worse*); friction is what
holds it. (ii) The rigid signature is **small and noisy** at 12 iterations — a
genuine flex-scale effect, not a clean phase-locked ripple (ring-band corr with
the lower mode ≈ 0.15). So the **clean, robust** effect remains the modal↔modal
transfer; the rigid-ride is an honest **partial** N3 win, enabled where friction
makes it safe. Full go/no-go (the X1-style robustness matrix + augmented-Q clamp)
is still N3 proper. Tests: `tests/avbd_native/test_modal_contact_ride.py`.

## Interactive viewer

`scripts/run_native_scenes_viser.py --scene cargo` — the **cargo scene is now the
4-cube network stack** (resting | impactor | offset stack). The network is ON by
default with a **live "modal contact network" checkbox**: toggle it and the
stacked (orange) cube's ripple appears/vanishes on the next step (the flag is
read each substep, no rebuild). Cube-flex exaggeration starts at ×200 so the ring
is visible immediately; raise "cube flex ×" for more. AVBD-only (the network is
native to `Solver6DOF`; the scene forces AVBD and the HUD shows it). `--no-network`
starts with it off. Multi-deformable rendering: all four cubes are drawn as their
true `Φ·a` surfaces.
